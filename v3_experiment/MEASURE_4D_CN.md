## 3. 效应分解（能量，mJ）

```
A0' 基线(全 ANN)       179.69
A1  仅视觉→脉冲         28.75    -84.0%
A2  仅文本→脉冲        172.98     -3.7%
A3  两者都换            22.05    -87.7%
A4  前端+融合全脉冲     20.90    -88.4%
```

- **视觉脉冲化贡献几乎全部收益**（−84.0%）；**文本脉冲化只贡献 −3.7%**。
  原因是结构性的：DINOv3 视觉占 MACs 的 88%，而 sootspike 与 BERT **参数量几乎相同**（同构替换），
  文本侧的稠密算子在 21 token、224 分辨率下本就很小。
- **超加性**：若两个替换独立可乘，A3 应 ≈ 27.68 mJ，实测 22.05 mJ（**再低 20.3%**）。
  即"视觉已经脉冲化之后，再把文本脉冲化"的边际收益，比单独看文本时更大。
- A4 = A3 + 脉冲融合，再省 1.15 mJ（−5.2%）。

## 4. 口径与方法（写论文必须一起声明）

### 4.1 突触操作计数
- **逐算子按实际输入张量判定**，不按类名硬编码：
  - 输入取值 ⊆ {0,1}（二值脉冲）或 ⊆ {0,¼,½,¾,1}（SDT-V3 的 `MultiSpike`，5 级量化）→ **脉冲算子**，
    `ACs = Σ|活动| × fan_out`（每活跃输入只做 fan_out 次累加），另报只数非零的保守口径 `Σ nnz × fan_out`；
  - 否则按 ANN：`MACs = 输出元素数 × fan_in`。
  - 两种口径在"活动密度 d"下等价于 `ACs = d × MACs`，自洽。
- 用 `TorchDispatchMode` 拦截 `aten.mm/bmm/addmm/matmul/convolution`（**SDT-V3 用的是 `@` 运算符**，
  模块 hook 抓不到，必须走 dispatch）。
- **T 无需显式相乘**：本代码库用 `repeat_time` 把时间步展开进 batch 维（`[T,B,N,D]`），
  稠密计数天然含 T 倍。

### 4.2 能量换算
`E = MACs × 4.6 pJ + ACs × 0.9 pJ`（45nm CMOS 惯例）。
"全 ANN 等价"= 把脉冲算子的稠密等价量也按 4.6 pJ 计，即**同一网络若不脉冲化要花多少**。

### 4.3 三个必须声明的坑（都已在脚本里处理或标注）
1. **GPU 上是 dense PyTorch 模拟，脉冲不产生真实节能，也不省时间**。
   实测延迟 A0' 28.0 ms、A4 151.0 ms：**算子更少的 A4 反而慢 5×**（T 展开 + 小 kernel 启动开销）。
   能耗数字是"若部署在事件驱动脉冲硬件上"的**理论上界估计**。
2. **首次前向含一次性常数**：SmoothSpike 的 `msign(H1)`（`spikingbert_rot_inf.py:1019`）惰性缓存，
   首次前向多算 ≈6.8G MAC（5 步 × 3 个 768×768 矩阵乘）。脚本**先 warmup 再统计**，
   否则 batch=1 能耗会被高估 2.5×，且 batch=1 与 batch=16 不可比。
3. **抽样确定性**：分类用的取值集合判定改为等距抽样（原先随机抽样会让同一权重在不同臂间抖动 0.2%）。

### 4.4 自洽性检验
batch=16 的总能量 ÷ 16 与 batch=1 **逐位吻合**（A4 334.51/16 = 20.91 vs 20.90；A1 459.96/16 = 28.75 vs 28.75；
A0' 2874.98/16 = 179.69 vs 179.69）→ 测量口径内部一致。
