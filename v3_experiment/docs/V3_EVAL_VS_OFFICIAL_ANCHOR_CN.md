## 2. v3 的 goal 失分集中在单任务 task5(对齐剔除口径已计算)

v3 的 libero_goal task5(**push the plate to the front of the stove**)仅 **2%(1/50)**,
其余 9 个任务 72%–100%。视频复盘确认:两次失败逐帧近重复、均为推压过冲后**跑满 300 步
超时**(详见 `V3_OPTIMIZATION_PLAN_CN.md` §1-D3),是系统性误判,非随机崩坏。

**官方锚点同一任务表现(json 实证,2026-09-10)**:**47/50 = 94%**——同一任务、同一协议
(fp32 · seed 7 · 50 trials · chunk 12 · open-loop 12 · commit 8f1084e)下官方近乎不失败。
结论:**task5 失败是模型行为差异,协议与任务歧义因素已排除**;该任务贡献 goal 差距的
46/68 ≈ 2/3。**D1 补充(2026-09-10,见 §5)**:EMA 口径下同一任务 98%(49/50)——raw 上
的失败是真实发生的现象,但该行为对权重选择高度敏感,不能归为模型固有缺陷。原计划用
v2(SpikingLM 脉冲文本,同批训练血统)同任务表现收窄候选解释,但 **v2 80k 未训成
(见 §4 第 2 条)**,归因只能依赖后续 A1/A2 消融。

## 4. 怎么读这张表(重要边界)

1. **这不是单变量对照。** v3 与官方锚点在训练配方上处处不同:v3 是从零 80k 步、单卡全局
   batch ≈56–64、KD 蒸馏(官方 LIBERO ckpt 为 teacher,feature 0.25/action 0.5)、SDT-V3
   SNN 视觉 + Spike2Max 融合;官方锚点是官方自己的训练产物。本表的官方锚点用于**钉协议与
   环境上限**,不用于归因 sootspike。
2. **v2 对照产物当前无法取得(2026-09-10)**:在所有可查范围内未发现 v2 80k 产物——
   源机 amax 只有 09-05 的 2k smoke(`turbovla_v2_smoke_2000.pth` + 2 条单卡日志,smoke
   配置与配方文档一致);新集群唯一一次启动(09-07 09:11,4 卡 · 全局 256 · spikinglm
   frozen · KD 0.25/0.5)前 1000 步健康,30 分钟后中断于 step 1015/80000,无 checkpoint
   (日志在 /data,疑为让卡给 v3);`CLUSTER_SETUP_CN.md` 预期产物目录
   `package/output/train_v2/checkpoints/` 至今为空;两台 worker 节点 + 全部常规根目录
   扫描均无。**据此断言的是"当前无法取得 v2 对照",不断言 v2 实验不存在**。因此
   "v3 vs v2"实测对照目前缺位,当前可执行的同文本、不同 batch 配方对照是 A1
   (见 `V3_OPTIMIZATION_PLAN_CN.md`;注意固定 80k 更新下 batch 与累计样本量同时改变,
   非纯单变量)。
3. **已完成(2026-09-10)**:官方锚点逐任务 json(amax 机器
   `$PKG/output/eval/official_clean_8f1084e/results/`)已同步到
   `/data/260010028/dwh_vla/anchor_export_20260909/`(summary + 四套件 json,
   1854/2000 = 92.7%,协议字段与本表逐项一致)。本文件 §1–§3 的官方逐任务数字均出自
   该目录。
4. **当前可下的结论**(四套件口径,含对齐剔除):
   - object 类(简单抓放):完整 v3 系统层面未观察到明显退化(99.2 vs 98.8,噪声内);
     组件级归因不作,官方成绩仅为参考基线;
   - spatial / goal / libero_10 存在真实落后(−15.4 / −13.6 / −16.4pp);失分形态不同——
     goal 集中于单任务(task5 占 2/3,同剔后 −4.9pp 已接近噪声),spatial 与 libero_10
     同剔最弱任务后仍 −11.3 / −12.4pp,是跨任务面状差距;
   - goal task5 的失败是模型行为差异(官方同协议同任务 94%),协议与任务歧义已排除;
   - v2 对照臂不存在(见第 2 条),**不把差距归因于文本 spike 化**(视觉骨干、融合、
     训练配方、KD 都可能贡献),归因依赖后续 A1/A2 消融。

### 解释边界(2026-09-10 评审定稿)

1. **当前可确认**:该 ckpt 的 EMA 与 raw 行为差异极大;raw 的 task5 崩塌不是唯一、稳定
   的模型行为;EMA 值得作为独立权重口径继续评测。**EMA 增益不是无条件的**——object
   (raw 已近官方)持平微降,增益集中在 raw 落后的套件。§2 视频描述的是 raw 权重的真实
   失败现象,仍然成立,但不能归为模型固有缺陷。
2. **不能推出**:"训练末期权重不稳定实锤"(单终点两份权重只说明**权重选择敏感**;加固
   手段 = 补 70k/75k/80k 的 raw/EMA 曲线,单套件 goal 即可,候选不排期)、"大 batch 方向
   已验证"(A1 仍是验证实验)、"真实能力更接近官方"(应为:EMA 口径下 goal 观测成绩
   接近官方 raw 锚点)。
3. **后续顺序(四步已全部完成)**:spatial EMA ✅ → 增益确认为全局(spatial/goal)→
   补 object/libero_10 EMA ✅(2026-09-10)→ raw 与 EMA 分别报告(本节四套件表)。
   **下一步:决定 A1 配置与是否采用 EMA 部署**——EMA 若采用,须预注册 raw/EMA 选择
   规则并对所有模型统一执行;A1 的价值重心从"救成绩"转向"检验 batch/累计样本量假设
   与 v4 前置验证"。
